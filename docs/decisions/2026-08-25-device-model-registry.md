# 决策：设备模型注册表（物模型）——元数据唯一来源原则落地

> **状态**：accepted
> **日期**：2026-08-25
> **原则（宪法级，rs-iot 必须遵循）**：**元数据必须有唯一性和唯一的来源与管理入口；否则系统设计就是失败的。** 设备与设备标签的元数据只能有一个出生地（模型+设备注册表）、一个管理面（其 REST/UI），任何采集实现（内置插件/lua 脚本/外置插件）都不得自行创建真实设备与标签。
> **实施计划**：[2026-08-25-device-model-registry-plan.md](../designs/2026-08-25-device-model-registry-plan.md)（四期 M-1~M-4，TDD）
> **背景授权**：用户明示——lua 脚本系统与外置插件**可以调整甚至重构**；rs-iot 处于初级阶段（工程验证级，核心管道性能已验证、业务面未达生产级），无现场存量负担，是结构性重构的唯一窗口。因此**不做运行时兼容层，不搞灰度双模式**，按第一性原理一步到位。

## 1. 问题：当前元数据体系的三个结构性缺陷

Phase 1a Tag Registry（[2026-08-24-tag-registry-plan.md](../designs/2026-08-24-tag-registry-plan.md)）解决了"元数据可见可治理"，但没有解决"元数据唯一出生地"：

| # | 缺陷 | 现状代码位置 | 后果 |
|---|---|---|---|
| 1 | **无型号层** | `InstConfig.devices[].children[]` 内联点表（`src/types.rs:194-206`） | 50 台同型号设备（如威胜 DTZ34Z 电表）点表抄 50 遍；型号级策略（统一归档/死区）无处表达 |
| 2 | **多出生地** | 内置=配置点表；lua=脚本 `ctx:set_value` 动态产生（`lua_core/api/mod.rs:468-526`）；sidecar=DataUp 帧上送任意 tag（`sidecar_client/mod.rs:69-79`） | 元数据来源不唯一，违背本决策的宪法原则 |
| 3 | **地址与语义耦合** | `ChildSpec.value` 既是协议地址（`holding:0:f32`）又是标签身份来源 | 模板无法复用：每台设备地址不同，点表只能各写各的 |

## 2. 决策内容（四项）

**D-M1 全局设备实体（一步到位，不分阶段）**
设备是全局唯一物理实体（`devreg` 表：devid + 模型引用 + 实例化参数 + 属性覆盖），采集器实例只**绑定**设备（N:M），不拥有设备。物理世界映射：那台电表换网关/换采集器，devid、属性、历史连续。现状 `dev2inst` 多宿主并记已隐含承认设备身份独立于实例，本决策将其显式化。

**D-M2 物模型层（型号即模板）**
`devmodels` 表：型号元数据（厂商/型号/类别）+ 参数声明 + 标签模板集合（名称/类型/单位/描述/读写/**参数化地址**/**型号级默认属性**）。标签是"乐高最小对象"，设备模型是拼装组件，采集器实例是底板。属性合并语义：`effective(tag) = 模型默认 ∪ 设备覆盖`（改模板 → 全部同型号设备生效；单台特殊化走覆盖）。

**D-M3 tags 表退役，被设备注册表吸收；出口登记转型为发现队列**
Phase 1a 的 lux `tags` 表（运行时属性卡）被 `devreg` 的 overrides 字段吸收——元数据表数量不增反减。`note_once` 出口登记转型为**发现引擎**：数据流中未建模标签进 `discoveries` 队列（不自动入正式册），人工确认后一键建模（adopt）。发现是建模工作流的入口，不是兼容手段。

**D-M4 严格校验，无灰度**
lua `set_value/collect` 与 sidecar DataUp 在宿主层过校验闸（devid ∈ 本实例绑定 ∧ tag ∈ 该设备模型标签集），不过闸进 discoveries。默认严格，不做"发现模式灰度切严格"的过渡开关（无存量负担，直接干净）。

## 4. 备选与否决理由

- **渐进兼容方案**（内联点表自动提升为隐式模型、运行时双结构并存、灰度开关）：否决——用户明示可重构且无生产存量；运行时兼容层是长期债，一次性迁移命令（旧内联 children → 隐式模型 + devreg 条目）成本更低。
- **设备实例继续内联在采集器配置**（两阶段走）：否决——多宿主并记已证明设备身份独立于实例是既成事实，内联是过渡态冗余。
- **模型属性在实例化时物化拷贝**：否决——模板更新后 50 台不跟随，失去型号级集中管理的核心价值；改为动态合并 + flush 侧物化缓存（性能与集中管理兼得）。

## 5. 不破坏性声明（夯实而非推倒）

**冻结不动**：pipeline/dispatcher/worker、lux rtdata 写路径、`tag_key()` id 体系、50 万点/秒吞吐资产、KSUB 机制、tsink 集成设计（master plan ADR 不变）——模型化只发生在**配置与元数据面**，与数据面正交。

**演进而非重写**：`tag_key`/`TagProps` 结构原样保留；`note_once` 的 once-set 去重与缓存模式换壳复用（发现引擎）；`glob_match` 复用（批量建模）；Phase 1a 的 e2e 方法论延续。约半数 Phase 1a 存储代码会被替换——初级阶段付此代价换元数据唯一来源，值。
